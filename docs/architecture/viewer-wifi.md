# Просмотр через Wi-Fi

## Дополнение: плеер и автоматическое открытие

После 16:20 26 сентября плеер дополнен явными состояниями ожидания/паузы,
обработкой offline/online и pagehide/pageshow, ограниченным повтором соединения
1/2/4/8 секунд и полноэкранным CSS-режимом на случай отказа браузерного API.
Ручной Stop сохраняется после возврата сети; старый ответ WHEP не оживляет закрытый
сеанс. Отсутствующие браузерные счётчики показываются прочерком. Кнопки рассчитаны
на касание, в полном экране доступен выход. Автовоспроизведение остаётся muted /
playsinline, при запрете браузера нужна кнопка «Смотреть».
Проверка: 7 JS-сценариев и 11 тестов сервера/сетевого выбора прошли.
После обновления в реальном браузере проверены живые 1280×720 / 30 FPS,
вход/выход полного экрана и Stop → Смотреть с восстановлением видео. Это проверка
браузера Mac; соответствующие действия на iPhone ещё требуют проверки.

Желаемый пользовательский сценарий: подключение к FIT-LAB → системное окно
с иконкой и кнопкой «Смотреть» → плеер. Надёжную поддержку этого сценария нужно
реализовать в отдельной службе точки доступа, а не только в HTML. Текущая раздача
macOS продолжает работать без этого портала; автоматическое окно не заявлено.

Для следующего этапа нужны:

1. Выбранный AP/backend и привилегированный установщик с обратимыми настройками.
2. DHCP option 114 с URL CAPPORT API и настоящий TLS-сертификат для управляемого
   домена. Поддержка общего DNS/сертификата на офлайн-стенде требует отдельного решения.
3. Согласованное состояние доступа каждого клиента, короткая страница входа и
   отдельный обычный браузерный плеер. Не объявлять captive=true без реального
   состояния сетевого доступа и не блокировать интернет ради имитации успеха.
4. Портал должен быть доступен при остановленном приёме и показывать ожидание;
   вход зрителя не запускает RX, запись или управление камерой.
5. Испытания первого/повторного подключения, приватного MAC, заблокированного
   экрана и iOS/Android; OS может показывать уведомление вместо окна. Повторное
   открытие на каждом подключении нельзя гарантировать одним сервером.

Домена, сертификата и установленной службы CAPPORT сейчас нет. Настройки DHCP/DNS
и пароль действующей сети ради этой подготовки не менялись.
Источники: [Apple CAPPORT](https://developer.apple.com/news/?id=q78sq5rv),
[RFC 8908](https://www.rfc-editor.org/rfc/rfc8908.html),
[WebKit: video policies](https://webkit.org/blog/6784/new-video-policies-for-ios/).

## Действующая трансляция

На Mac основное видео и дополнительная трансляция имеют разные процессы.
Веб-ветка превращает исходное H.265/H.264 в H.264 до 30 FPS через VideoToolbox,
не меняя кодек камеры. При переполнении отбрасываются целые декодированные кадры,
а не куски сжатого потока. Изменения параметров и автосмена камеры во время
трансляции заблокированы.

Локальная страница: HTTP 8890; MediaMTX WHEP: 8889; WebRTC media: 8189 UDP/TCP.
Встроенный плеер сохраняет пропорции, имеет полный экран, остановку и восстановление.
FPS, скорость, разрешение, потери и средний буфер берутся из getStats() данного
браузера. Буфер браузера не объявляется сквозной задержкой радиокамеры.
Сервер страницы не выдаёт файлы, ключи, настройки или управление камерой.

На Mac используется штатный «Общий интернет», отдельный от радиоприёмников.
Подготовлено: источник AX88179B (en6), выход Wi-Fi, имя FIT-LAB, WPA2/WPA3,
канал 11. Раздача включена: bridge100 192.168.50.1/24, DHCP
192.168.50.2-192.168.50.254. Ethernet en6 получает 192.168.2.39 от роутера;
выход в интернет по en6 проверен отдельно. Исходный диапазон 192.168.2.0/24
конфликтовал с роутером. При первом исправлении неверный End=.0 остановил DHCP;
ошибка выявлена по bootpd и исправлена на .254. Проверен фактически созданный
`/etc/bootpd.plist`, а не только адрес bridge100. Клиенты получили .50.2 и .50.3.

Изменение подсети выполняется только при выключенной раздаче утилитой Apple
`scutil --prefs`: `tools/configure_viewer_subnet.sh`. Пароль/остальные поля NAT
сохраняются. Неподписанная нативная SCPreferences-утилита получила отказ ОС и удалена.
В UI добавлены проверка пересечения подсетей и некорректного диапазона DHCP,
автовыбор bridge100 и исключение VPN-адресов. Новая ошибка сети прекращает только
дополнительную трансляцию, основной приём не останавливается.

Для будущего мастера на Linux: NetworkManager/hostapd — отдельная служба,
локальная подсеть 10.42.0.0/24, отдельный AP-адаптер, изоляция клиентов,
без маршрутизации в управляющую LAN по умолчанию. Параметры подготовлены в
`/Volumes/FIT-LAB/deployment/master/viewer-wifi.json`; это проект конфигурации,
не установленный сервис. Выбор аппаратного H.264 кодировщика требует модели платы.
WFB RX1/RX2 не используются одновременно как точка доступа для телефонов.

Проверены страница, иконки, manifest, HEAD и запрет произвольных путей. Выход H.264
Baseline 1280x720 декодирован ffmpeg: 901 кадр за 30 секунд, ошибок декодирования
нет. В текущем проходе браузер Mac действительно показал изображение, около 30 FPS,
0% потерь в наблюдавшихся отсчётах. Пользователь подтвердил просмотр на другом
компьютере и подключение iPhone 17 Pro Max к Wi-Fi; просмотр на iPhone пока требует
подтверждения. Ранее браузер был недоступен инструменту, этот исторический блок
больше не мешает чтению страницы/скриншота. Последующая автоматизация кликов вкладки
вернула ошибку принадлежности сессии; Stop/Start плеера в GUI не объявлены проверенными.

Плеер восстанавливает соединение при отсутствии первых кадров/зависании, отменяет
старые WHEP-запросы, очищает статистику и даёт одну кнопку при запрете autoplay.
Веб-иконка Vector, apple-touch-icon, standalone manifest и раскрываемая подсказка
готовы. Это не включает автоматическое открытие страницы при подключении к Wi-Fi.

Автооткрытие на личном iPhone: один раз создать автоматизацию «Команд» для сети
FIT-LAB и действия «Открыть URL». Это действие на телефоне; приложение Mac не может
настроить личную автоматизацию за пользователя. Для общего автоматического окна
зрителей нужен captive portal: отдельная служба точки доступа, DHCP option 114,
HTTPS API с доверенным сертификатом и согласованное состояние доступа. Такого
сервиса сейчас нет. Не подменять его фиктивным HTTP endpoint и не ломать проверки
интернета ради появления окна. На Linux это часть будущего проверенного AP-профиля.

Источники: [Apple — общий интернет](https://support.apple.com/en-mz/guide/mac-help/mchlp1540/mac),
[MediaMTX — Web browsers](https://mediamtx.org/docs/read/web-browsers).
Дополнительно: [Apple captive network](https://developer.apple.com/news/?id=q78sq5rv),
[Apple Wi-Fi automation](https://support.apple.com/en-au/guide/shortcuts/apde31e9638b/ios),
[WebKit Home Screen](https://webkit.org/blog/17333/webkit-features-in-safari-26-0/).
