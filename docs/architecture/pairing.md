# Сопряжение камер — 26.09.2026

LAN нужен для первого сопряжения каждой камеры и восстановления незавершённой
установки. Знакомые камеры выбираются по радио без генерации новых ключей.

## Реализация

- Каждая камера: отдельная пара WFB, SSH-отпечаток, частота, ширина и кодек.
- `data/config/bindings/` содержит публичные профили; `private/bindings/` — ключи.
  Рабочий ключ приёмника: `private/runcam/gs.key`. RX1/RX2 используют одну пару.
- PyNaCl/libsodium генерирует случайные X25519 ключи в формате WFB. Камерная часть
  передаётся только через stdin закреплённого SSH-соединения. Секреты не журналируются.
- Камера сохраняет старый ключ и откатывается без подтверждения. Проверка новой
  пары требует декодированных RF-кадров, ответа TX и SSH nonce через радиоканал.
  Ранний boot hook восстанавливает незавершённую установку после перезагрузки.
- Повторное сопряжение той же пары возвращает `unchanged`, без перезапуска камеры.
- Локальный выбор имеет журнал восстановления и не создаёт ключи заново.
- Радиоуправление проверяет SSH-отпечаток выбранного профиля, а не последнего LAN IP.
  Подтверждённые изменения частоты/ширины/кодека сохраняются в профиль этой камеры.

Старая рабочая пара первой камеры импортирована из сохранённой резервной копии.
Её уникальность относительно заводского ключа не доказана. Новая пара второй
камеры сгенерирована и проверена. Импорт не означает ротацию ключа первой камеры.
Права файлов 0600, каталогов 0700; Owners Disabled на текущем APFS не означает
защиту от других локальных аккаунтов или шифрование накопителя.

## Автоматический поиск

До видео отдельный процесс слушает сохранённые частоты. Две разные частоты
слушаются двумя адаптерами параллельно; при большем списке или одном адаптере
выполняется ограниченный циклический поиск. TX в режиме поиска отсутствует.
После выбора оба RX принимают выбранную камеру. Настройка адаптера использует
уже проверенный аппаратный профиль, без повторного чтения EFUSE при каждом ходе.

Для определения проверяются зашифрованное WFB-объявление сессии и минимум три
различных аутентифицированных data-пакета. USB, RSSI, имя и Link ID недостаточны.
Копии одного пакета с двух RX не дают дополнительные подтверждения. Два профиля
с одной парой ключей неразличимы и не выбираются автоматически. Это не защита от
полного радиоповтора записанного потока: для неё нужен отдельный свежий challenge.

«В эфире» означает недавние подтверждённые пакеты. «Сохранена» не означает, что
камера включена. При нескольких найденных камерах старт требует выбора. Во время
видео текущая камера удерживается, поиск не отнимает RX для других частот.
Камеры на текущей частоте можно опознавать в фоне; остальные остаются сохранёнными.

Последовательное включение: после 6 с отсутствия RTP и ответа TX допускается
смена на опознанную камеру; поиск другой частоты ждёт 12 с и готовности RX.
Запись, трансляция, сопряжение и транзакция смены частоты блокируют автосмену.
«Стоп» отменяет также отложенный перезапуск. При смене камеры процессы сейчас
перезапускаются — бесшовное переключение не обещается.

## Подтверждено

- Новая камера: ключ установлен, RF-видео и SSH через радио проверены.
- Повторный LAN: `unchanged`, без замены ключа и перезапуска.
- Поиск реальной камеры: 4,432 с, два RX на разных частотах.
- Намеренно выбран ключ другого профиля: автопоиск восстановил активную камеру,
  получено 849 кадров, 1280×720, TX отвечает. Камерные ключи в тесте не менялись.
- Живой GUI, отдельный замер: 7,883 Мбит/с, декодер 119,9 FPS, окно 60 FPS,
  22 817 выходных пакетов, потерь 0, ошибок расшифровки после прогрева 0,
  восстановлено FEC 174; перезапусков приёмников и декодера 0.
- 182 программных теста прошли перед последней доработкой проверки файлов профиля.

26 сентября пользователь сообщил, что переподключение другой камеры работает;
в телеметрии после этого подтверждена камера 1 на 5200 МГц. Это не контролируемый
тест полного цикла обеих камер. Не подтверждены: две одновременно, все сценарии
потери питания, дальность и сквозная задержка.
Намеренно выбранный чужой ключ не выдаётся за физическую замену камеры.

Формат проверен по закреплённому исходнику WFB-NG и
[описанию шифрования](https://github.com/svpcom/wfb-ng/wiki/Encryption).

## Вход и сохранённые камеры

После обнаружения знакомой камеры приложение пробует пароль её SSH-отпечатка,
затем общий пароль от первого успешного входа. Другая камера со своим паролем
получает отдельную запись и не заменяет общий пароль. Проверка SSH-идентичности
всегда выполняется до передачи пароля; новый LAN-отпечаток требует подтверждения.
На Mac пароль хранится системной Связкой ключей, в проект/отчёты/пакеты переноса
не записывается. На Linux пока доступно только хранение в памяти сеанса.
Недоступное хранилище обозначается как сохранение до закрытия приложения.

Форма появляется при отсутствии или отклонении пароля. Сетевой сбой не считается
неправильным паролем; автовход повторяет только чтение, до трёх попыток с паузой.
Записи параметров автоматически не повторяются. После входа читаются настройки
камеры и передатчика, открывая частоту/мощность без отдельного входа.

«Удалить из списка» помечает публичную привязку как удалённую: автопоиск её
исключает, выбор запрещён. При удалении текущей выбирается другая сохранённая,
если она есть. Последнюю удалённую привязку нельзя использовать для запуска.
Ключи сохраняются для действия «Восстановить». Изменение списка блокируется
во время приёма, операций и незавершённого сопряжения; применяется файловая
блокировка приёмника. Это удаление из списка, не уничтожение секретов.
