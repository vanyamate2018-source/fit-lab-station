# FIT-LAB: единый комплект, автоматические роли

Статус: согласованное направление от 26.09.2026, ещё не реализовано полностью.

## Роли

Роль оборудования остаётся явной: мастер остаётся мастером, приёмник остаётся приёмником. Одинаковая полнота интерфейса на обоих устройствах не меняет их назначение. Пользователь выбирает, где настраивать и проверять оборудование.

Один продукт с отдельными службами приёма, управления и интерфейса. Сборки и зависимости подбираются по ОС и архитектуре; «один комплект» не означает один исполняемый файл для всех ОС.

- Мастер с USB-приёмниками: «Встроенный модуль», локальный приём.
- Мастер без USB, с подтверждённым приёмником по LAN: «Приёмник по LAN».
- Приёмник с дисплеем, без активного внешнего мастера: локальный интерфейс для самостоятельной проверки.
- Приёмник под управлением внешнего мастера: радио/запись/обнаружение продолжаются, полноценный локальный интерфейс остаётся доступным для проверки и отладки; отображение не зависит от роли управляющего.
- Приёмник без дисплея: службы работают без графической оболочки; состояние доступно мастеру.

Само появление Ethernet, роутера или интернета не означает обнаружение мастера. Нужны проверенная идентичность, совместимость версии протокола и подтверждённое соединение. Внешний мастер получает ограниченную по времени аренду управления. Один активный владелец записывающих команд; остальные клиенты только смотрят. Утрата аренды не останавливает приём или запись. Переход управления между двумя доступными интерфейсами не должен вызывать повторную инициализацию USB. Режим выбирает пользователь; автоматическое определение предлагает подходящий модуль, не запрещая работу на другом экране.

Если одновременно доступны встроенный и удалённый модули, интерфейс показывает оба. Предпочтение удалённому приёмнику применяется после проверки готовности; смена действующего источника не должна рвать запись без явного решения пользователя. Несколько удалённых модулей требуют выбора; нельзя выбирать по последнему пакету обнаружения. Возврат LAN не должен создавать борьбу двух мастеров.

## Установка и автозапуск

Подготовить подписанные загрузчики для macOS, Windows, Linux ARM64/x86_64. Первый запуск определяет платформу, проверяет подписанный манифест и хеши, докачивает только необходимые компоненты, проверяет зависимости и разрешения. Установка возобновляется после обрыва, обновление допускает откат. Предусмотреть офлайн-комплект.

Автозапуск: служба приёмника запускается независимо от интерфейса. На Linux - системная служба и отдельный сеанс UI; на Mac/Windows - штатные механизмы соответствующей ОС. Настройка автозапуска прозрачна пользователю и обратима. Не устанавливать автозапуск в текущей отладке без готового пакета.

## Лицензирование - будущий этап

Ключ, привязанный к одному устройству; месяц или бессрочно; опрос остатка сеансов. Отдельно определить понятие сеанса, сочетание срока и квоты, работу без интернета, перенос после ремонта, восстановление лицензии и сервер выдачи. Применять подписи лицензии и проверку целостности; обфускация/шифрование приложения не заменяет криптографическую проверку. Лицензионная ошибка не должна внезапно прекращать уже начатый приём. Механизм пока не внедрён.
