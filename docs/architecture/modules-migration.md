# Мастер-пульт и отдельный приёмник

План следующего этапа. Перенос на одноплатник начинается после проверки текущей
радиолинии; работоспособность Linux-приёмника этим документом не заявляется.

## Интерфейс сейчас

В нижней навигации: Видео → Радиолиния → OSD → Модули → Система.
Вверху — компактный счётчик присутствующих модулей. Два USB RX составляют один
локальный приёмный модуль. Счётчик означает присутствие, а не пройденную авторизацию.

В разделе «Модули» локальная карточка показывает реальные этапы:
обнаружение USB → пакеты RX1/RX2 → видеокадры → ответ TX. Подключение USB само
по себе не зажигает зелёный статус приёма. Сетевые карточки отображают тип, имя,
ID, наблюдаемый адрес и состояние. Потерянная карточка остаётся в списке текущего
сеанса, при возврате heartbeat меняет состояние; уведомления находятся вне видео.
Анимации карточек останавливаются, когда раздел скрыт.

UDP hello/heartbeat сейчас подтверждают только присутствие: «Обнаружен · нужна
привязка». Готовность, полномочия и работоспособность не выводятся из присланного
списка capabilities. Готового защищённого мастера привязки LAN-модулей пока нет.

## Разделение работы

| Мастер-пульт | Приёмный модуль |
|---|---|
| Интерфейс и профили устройств | USB-адаптеры и радиодрайверы |
| Декодирование и вывод видео | RX1 + RX2, удаление дублей, FEC и расшифровка |
| Выбор параметров, показ результата | TX, связь с камерой, применение и чтение результата |
| Запись/трансляция на выбранный накопитель мастера | Исходный сжатый поток по Ethernet |
| Журнал действий и состояние модулей | Автовосстановление USB, аппаратные журналы и ключи |

Возможность записи на накопитель приёмника — отдельная capability и отдельный
выбор в интерфейсе. Объединённый список дисков не должен скрывать, где физически
хранятся файлы. Повторное кодирование между приёмником и мастером не требуется.

Мастер управляет радиолинией через приёмник. Рабочие процессы `wfb_rx/wfb_tx`,
контроль USB и камерный SSH relay живут на приёмном одноплатнике. MAC-специфичный
IOKit и абсолютные SSD-пути не переносятся на Linux. Протокольные парсеры, FEC-
интеграция, состояния восстановления и проверяемые команды остаются общими.
Сейчас `receiver/service.py` — каркас; это не готовый Linux daemon.

## Включение по кабелю

1. Мастер открывает интерфейс и запускает обнаружение, не ожидая наличия модулей.
2. Приёмник загружается автономно, проверяет конфигурацию/ключи/адаптеры и объявляет
   стабильный ID, версию API и заявленные возможности.
3. Мастер показывает новое устройство. При первом подключении выполняется привязка
   идентичности по отдельному защищённому каналу. IP и UDP hello не являются доверием.
4. Для уже привязанного модуля проверяются идентичность, версия API и фактическое
   здоровье. Этапы показываются сверху: обнаружение → проверка → инициализация → готов.
5. Пользователь нажимает «Начать приём». Автозапуск системной службы не означает
   автоматический запуск радио, видео, записи или трансляции после старта приложения.

Ethernet: сначала использовать существующий DHCP; прямое соединение без роутера
должно поддерживаться отдельным проверенным профилем link-local. Не менять общую
сетевую конфигурацию Mac и не назначать фиксированный адрес всем устройствам.
Наблюдать состояние интерфейса/адреса, обнаруживать смену адреса по стабильному ID.
Broadcast discovery остаётся поиском; адреса команд/видео предоставляет проверенный
модуль после согласования. Медиа и управляющий канал имеют отдельные очереди.

## Команды и разрывы

- Один владелец управления на приёмнике с ограниченным по времени lease.
- ID операции, ожидаемая версия конфигурации, срок исполнения и проверяемый результат.
- После разрыва мастер сначала читает результат незавершённой операции; настройки
  не переигрываются автоматически. Старые команды к прежней камере не исполняются.
- Логика изменения частоты с откатом работает на приёмнике и камере независимо
  от окна приложения. Закрытие мастера не должно оставлять половину переключения.
- Работающий RX продолжает приём при потере мастера. Уже начатая локальная запись
  на приёмнике продолжается согласно её политике; запись на отключённом мастере
  не объявляется продолжающейся. TX-команды требуют действующих полномочий.
- Потеря Control/CRSF или SDR не останавливает WFB. Модули инициализируются независимо.

## Подготовка одноплатника

Перед установкой зафиксировать модель платы, архитектуру CPU, ОС/ядро, Ethernet,
USB-контроллеры, питание двух адаптеров, накопитель и охлаждение. Подобрать и проверить
драйверы monitor/injection для фактического оборудования. Подготовить headless-сервис,
автозапуск, ограниченные журналы, проверку конфигурации, диагностический экспорт и
возврат предыдущей версии обновления. Внедрять поэтапно без перепрошивки камеры.

Приёмка: запуск без GUI; два RX и каждый отдельно; физический USB hotplug; обрыв и
возврат LAN; смена адреса; перезапуск мастера во время радиооперации; восстановление
питания; запись; сквозная задержка; ошибки ключа; несовместимость API; недоверенный
модуль; длительная нагрузка. После этого можно считать разделённую систему готовой.
