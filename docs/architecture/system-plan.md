# План системы FIT-LAB Station

## Неподвижные принципы

- Мастер-пульт отвечает за интерфейс и оркестрацию, но не заменяет специализированные модули.
- Модуль видеоприёма занимается только видеоприёмом, RX1/RX2, радиостатистикой и своим состоянием.
- Модуль управления отдельно отвечает за PAN/TILT, CRSF, INA219, IMU и физические входы/выходы.
- SDR-модуль независим от Broadcast.
- Сбой или перезапуск одного slave-модуля не должен останавливать остальные.
- Камерный OSD не меняется. Диагностика станции располагается вне изображения.
- Показатели не выдумываются: при отсутствии данных интерфейс показывает «—» или «Нет данных».
- Секреты, ключи, записи, IQ и пользовательские журналы не попадают в Git.

## Мастер-пульт

Слои:

1. UI — PySide6/Qt.
2. Station Core — состояние станции и журнал событий.
3. Module Registry — известные модули и их состояния.
4. Discovery/Transport — обнаружение и связь с модулями.
5. Media — видеопоток и запись.
6. Storage — накопитель и архив.
7. Hardware profiles — профили камер и совместимого оборудования.

UI не управляет сокетами, GPIO или WFB-ng напрямую. Все действия идут через сервисный слой.

## Сеть

Текущий UDP-код остаётся прототипом wire-format и heartbeat.

Целевая схема LAN:

- обнаружение модуля;
- первичная безопасная привязка;
- стабильный module UUID;
- проверка версии API и capabilities;
- heartbeat;
- защищённый управляющий канал;
- автоматический reconnect;
- один владелец управления и несколько read-only клиентов.

Видео, телеметрия и команды управления не должны зависеть от одного транспортного потока.

## Видео

Цель — принимать уже сжатый H.264/H.265 поток без лишнего перекодирования.

Пайплайн:

камера/передатчик → WFB-ng → Модуль видеоприёма → LAN → Мастер-пульт → декодер/экран

Запись по возможности ответвляется до декодирования. Ошибка записи не должна останавливать просмотр.

## Хранилище

Код и рабочие данные разделены.

На текущем Mac:

- /Volumes/FIT-LAB/project — Git-репозиторий;
- /Volumes/FIT-LAB/data — recordings, telemetry, logs, iq, backups, exports, temp.

На будущих SBC core-служба запускается с локального системного накопителя. Съёмный диск не должен быть обязательным условием загрузки core-службы.

## UI

Основной режим: Broadcast | SDR.

Broadcast:

1. Видеоприём
2. Модули
3. Камеры
4. Радиосвязь
5. Запись
6. Трансляция
7. Наведение
8. Диагностика
9. Настройки
10. Сервис

Интерфейс масштабируется от небольшого HDMI-дисплея до большого монитора. Боковая панель сворачивается.

## Безопасность управления

До завершения аутентификации сетевой модуль может только объявить себя и показать статус.

Неподтверждённому модулю запрещены:

- CRSF-команды;
- команды сервоприводов;
- изменение радиопараметров;
- reboot/shutdown;
- операции с ключами.

Критичные действия требуют доверенного control channel и явной проверки состояния.
