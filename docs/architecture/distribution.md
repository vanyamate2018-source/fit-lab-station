# Закрытые сборки FIT-LAB Station

Контрольная точка 26.09.2026. Это подготовка выпуска, а не объявление готовности
Windows или Linux. Текущая проверенная среда - конкретный Mac со стендом на SSD.

## Роли и варианты

| Вариант | Роль | Медиа | Статус |
|---|---|---|---|
| macOS arm64 | Мастер, текущий локальный RX | VideoToolbox / проверенный программный декодер | Стенд работает; переносимого установщика ещё нет |
| Windows x86_64 | Мастер с сетевым приёмником | GStreamer D3D11, отдельная проверка кодировщика | Запланировано, не собрано |
| Linux arm64 | Мастер с экраном | Декодер и кодировщик конкретной платы | Требуется модель платы и ОС |
| Linux arm64 | Приёмник без экрана | Приём исходного сжатого видео и TX | Требуются плата, ядро, USB и радиодрайвер |
| Linux x86_64 | Мастер / испытательный приёмник | VA-API либо проверенный программный вариант | Не собрано и не проверено |

Один интерфейс, общая модель камер и команд, отдельные платформенные службы.
Windows-мастер не должен импортировать macOS IOKit или управлять Linux monitor-mode
драйвером напрямую. WFB, будущие SDR и CRSF объявляют возможности через приёмный
модуль. Безопасное сопряжение сетевых модулей ещё не реализовано.

## Путь пользователя

1. Установщик создаёт одну иконку FIT-LAB Station.
2. Первый запуск определяет ОС, архитектуру, роль и свободное место.
3. Готовый основной пакет уже содержит интерфейс и среду исполнения. Недостающий
   медиапакет загружается по подписанному каталогу с понятным прогрессом.
4. После обрыва продолжается загрузка. Проверка подписи, размера и хеша предшествует
   установке. Пакет для другой платформы не принимается.
5. Приложение обнаруживает модули и знакомые камеры. Приём запускает пользователь.
   Профили, ключи и записи сохраняются отдельно от заменяемой программы.
6. Без интернета работает уже установленная версия. Предусмотреть полный офлайн-
   установщик с теми же проверенными компонентами.

Не устанавливать Homebrew, Python, компилятор или пакетный менеджер на пользовательскую
машину ради обычного запуска. Такие зависимости относятся к сборочной среде.
Системные разрешения и драйверы запрашиваются только при необходимости своей функции.

## Уже подготовлено

`shared/runtime_download.py` проверяет подпись Ed25519 каталога по закреплённому
публичному ключу, соответствие платформе, размер и SHA-256; поддерживает HTTP Range,
возврат к полной загрузке при игнорировании Range, кэш и атомарное завершение.
Проверены обрыв, неправильный диапазон, испорченный пакет, подмена каталога и отказ
от перенаправления на HTTP. Компонент только готовит файл: не распаковывает,
не выполняет и не устанавливает его. В работающий интерфейс обновлений ещё не включён.

Производственный ключ подписи и сервер обновлений не созданы. Ключ проверки должен
быть встроен в подписанный установщик; нельзя доверять ключу из скачанного каталога.
Не добавлять фиктивные URL или хеши. Манифесты готовых выпусков публикуются только
после сборки, тестов и подписания на соответствующей платформе.

## Что ещё требуется перед выпуском

- Убрать абсолютные пути SSD из платформенных адаптеров, сохранив текущий SSD-профиль.
- Отделить POSIX-блокировки/сигналы, хранилища секретов и запуск процессов от UI.
- Для GStreamer и его Python bindings подготовить совместимый закрытый runtime-пакет;
  наличие одной библиотеки Qt не обеспечивает воспроизведение.
- Собирать UI через pyside6-deploy/Nuitka на каждой целевой ОС. Пакет распространяет
  программу и ресурсы, а не каталог разработки. Компиляция не гарантирует невозможность
  анализа бинарника. Лицензии сторонних компонентов сохраняются отдельно.
- macOS: стабильная подпись Developer ID, notarization; Touch не переподписывать случайно
  при каждой сборке, иначе может потребоваться новое разрешение Accessibility.
- Windows: подписанный установщик, профиль GPU/медиакомпонентов, корректное обновление.
- Linux: пакеты или образ под конкретную плату, отдельные службы, udev и питание USB.
- Установщик выполняет проверку медиа, запуска и соединения до смены активной версии;
  сохраняет предыдущую версию и откатывается после неудачного запуска.
- Никаких обновлений во время записи, приёма или незавершённой команды камеры.
- Только один установщик меняет каталог кэша/версий; нужна межпроцессная блокировка.
- Раздача Wi-Fi: штатный механизм своей ОС; AP-адаптер отделён от WFB RX1/RX2.

На SSD `deployment/master` и `deployment/receiver` - внутренние исходные заготовки.
Они не являются пользовательскими установщиками и не предназначены для раздачи.
Публичные материалы: инструкция, список изменений, чек-лист. Закрытые: исходники,
сборочные журналы, ключи, сертификаты и инфраструктура выпуска.

## Приёмка каждого выпуска

Чистая машина без среды разработки; первый и повторный запуск; офлайн-режим;
возобновление загрузки; неверная подпись/платформа; нехватка места; откат обновления;
подключение приёмника по LAN; два RX и отключение одного; команды и откат частоты;
запись и веб-просмотр; поворот/разрешение/сенсор экрана; минимум длительный стендовый
прогон. Версию Windows нельзя помечать проверенной по результатам тестов на Mac.

Источники: [Qt - pyside6-deploy](https://doc.qt.io/qtforpython-6/deployment/deployment-pyside6-deploy.html),
[Nuitka](https://nuitka.net/user-documentation/user-manual.html),
[GStreamer для Windows](https://gstreamer.freedesktop.org/documentation/installing/on-windows.html).

## Уточнение владельца: полный установочный комплект

Тестовую сборку и рабочий проект оставить на SSD без перемещения. Для выпуска выбран полный офлайн-комплект с зависимостями. Окно установки показывает компоненты, проверку файлов, реальный прогресс и результат. Нельзя показывать фиктивный прогресс или считать исходники установленным приложением. Сейчас подготовлены состав и предварительное окно; автономные пакеты и установка ещё не готовы.
