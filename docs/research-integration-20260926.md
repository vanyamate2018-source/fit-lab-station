# Проверенные направления развития FIT-LAB, 26 сентября 2026

Источники сопоставлены с установленными версиями и кодом FIT-LAB. Возможность в
новой документации сама по себе не подтверждает её наличие в прошивке камеры.

## Что вошло в реализацию

WFB-NG учитывает количество принятых пакетов при выборе TX: сильный RSSI не
доказывает качественный приём. В FIT-LAB добавлено начальное наблюдение 1,5 с;
из адаптеров с не менее 80% лучшего темпа пакетов выбирается лучший RSSI.
Затем TX закреплён: смена только после подтверждённого завершения старого
процесса. Это ограниченная адаптация начального выбора, не полный перенос
алгоритма WFB-NG и не автоматическая регулировка мощности.

Источники: [WFB-NG releases](https://github.com/svpcom/wfb-ng/releases),
[Setup HOWTO](https://github.com/svpcom/wfb-ng/wiki/Setup-HOWTO).

Автовход выполняется вне UI-потока. Для Mac реализован узкий адаптер SecItem
со своим service/account и запретом модального запроса Keychain из рабочего
потока. Недоступность хранилища не останавливает видео и не сохраняет пароль
в открытом виде. Проверено повторным запуском приложения на настоящей камере.

Источники: [SecItemAdd](https://developer.apple.com/documentation/security/secitemadd(_:_:)),
[LAContext interactionNotAllowed](https://developer.apple.com/documentation/localauthentication/lacontext/interactionnotallowed).

## Что требует отдельной проверки оборудования

- Новые параметры Majestic `refPred`, `refEnhance`, `intraLine` меняют поведение
  при потере кадров, но зависят от SoC и версии. В актуальной документации
  часть перенесена из `fpv` в `video0`; старые пути могут игнорироваться.
  FIT-LAB получает схему конкретной камеры, поэтому новые поля нельзя просто
  вписать всем устройствам. Следующий шаг — проверка схемы и отдельный стенд
  потерь для поддерживающей прошивки. Камера в этом проходе не прошивалась.
  [OpenIPC encoder tuning](https://github.com/OpenIPC/wiki/blob/master/en/majestic-encoder-tuning.md).
- Jitterbuffer ограничивает ожидание отсутствующих RTP-пакетов; принудительный
  сброс по задержке меняет компромисс задержка/целостность кадра. Существующие
  счётчики поздних/потерянных пакетов сохранены. Настройку нельзя объявить лучше
  без сравнения на потере пакетов и при 30/60 FPS; новая «магическая» величина
  по статье не выставлялась.
  [GStreamer rtpjitterbuffer](https://gstreamer.freedesktop.org/documentation/rtpmanager/rtpjitterbuffer.html).
- WFB-NG поддерживает распределённые RX и динамические FEC/MCS. Это подходит
  будущему отдельному приёмному модулю, но нужны версии служб, доступный API и
  проверка на выбранной плате. Видео следует оставлять отдельным RTP-потоком,
  а низкоскоростные команды — отдельным каналом. Управление полётом отложено
  по просьбе пользователя.
  [WFB-NG](https://github.com/svpcom/wfb-ng).
