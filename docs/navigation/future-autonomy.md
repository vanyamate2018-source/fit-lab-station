# FIT-LAB Airborne Companion — будущий этап

## Назначение

Будущий бортовой одноплатник используется как high-level companion computer:
- расширенная навигация;
- управление миссией;
- логика контрольных точек;
- обработка дополнительных датчиков;
- связь с FIT-LAB Station;
- подготовка маршрута/цели для автопилота.

Он не заменяет realtime flight controller.

## Базовый принцип

```text
FIT-LAB Station
    ↕
Control / Telemetry Link
    ↕
Airborne Companion SBC
    ↕ MAVLink / supported FC API
Flight Controller
    ↓
ESC / servos / motors
```

Flight Controller остаётся ответственным за:
- стабилизацию;
- attitude/rate loops;
- motor outputs;
- базовый RC failsafe;
- Return/Home/Rally behavior;
- geofence;
- low-battery failsafe.

Companion отвечает только за high-level intent.

## Потеря связи

Предлагаемая иерархия:

1. Краткий пропуск:
   FC продолжает штатный режим в пределах настроенного timeout.

2. Потеря управляющего канала:
   FC самостоятельно переходит в заранее проверенный failsafe.

3. Возврат:
   при наличии валидной глобальной позиции — Home или заранее определённая Rally/контрольная точка.

4. Если companion жив:
   он может дополнительно сообщать статус/миссию, но не должен быть обязательным условием возврата.

5. Если companion завис:
   FC всё равно обязан выполнить базовый failsafe самостоятельно.

## Контрольные точки

Предусмотреть два понятия:
- **Home** — безопасная базовая точка возврата;
- **Rally / контрольная точка** — альтернативная безопасная точка.

В приложении нельзя молча подменять Home на произвольную точку.

Перед запуском:
- точка должна быть подтверждена оператором;
- координаты и высота должны быть валидны;
- маршрут должен учитывать geofence и заданную безопасную высоту;
- отсутствие позиции блокирует GPS-зависимый автоматический возврат.

## Будущие функции

После базовой версии:
- waypoint mission;
- loiter;
- return to rally;
- route preview;
- ETA;
- corridor/geofence display;
- выбор безопасной точки;
- автономное продолжение заранее загруженной миссии;
- резервная навигация по нескольким GNSS/датчикам.

## Что не делать первым этапом

- не писать собственный полётный контроллер на Linux;
- не переносить motor control на SBC;
- не делать SBC единственным failsafe;
- не разрешать автоматический полёт без стендовой и полевой валидации;
- не менять Home/Rally без явного подтверждения.
